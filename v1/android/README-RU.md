# ModKit Android 0.7.0

Приложение для локальной обработки двух файлов на Android 8.0 и новее.
Компьютер, root, сервер и интернет во время работы приложения не требуются.

1. Выберите `global-metadata.dat` и `libil2cpp.so` из одной сборки. Для получения
   установочного результата также выберите исходный APK игры.
2. Нажмите «Анализировать файлы». Встроенный Rodroid Il2CppDumper 0.7.0 создаст
   полный `dump.cs`, `script.json` и сопутствующие файлы. Они являются источником
   истины для списка методов. Обработка выполняется в фоновой службе;
   уведомление и экран показывают текущий этап. Доступна отмена.
3. Найдите нужный метод по имени, установите флажок, введите число (для bool 0/1).
4. Нажмите «Сохранить мод (ZIP)» либо «Собрать игру (APK)».

Поиск разбивает namespace, CamelCase и snake_case на отдельные слова. Поэтому
`hp` находит `HP`, `_hp` и `HitPoints` через смысловой словарь, но не
`SmoothPath`. Для игровых запросов по умолчанию исключаются `System.*`,
`mscorlib` и `UnityEngine.*`. В результатах также показываются подходящие поля,
свойства и методы, которые нельзя изменить текущим постоянным патчем; причина
указывается прямо в карточке.

Режим смыслового восстановления имён использует класс, сигнатуру, связанные
слова и набор игровых категорий. Он помогает при сокращённых и частично
искажённых именах, но не заявляет достоверное имя для полностью зашифрованного
символа без связей — такой результат помечается как неопределённый.

Кнопка «Сохранить полный дамп Rodroid (ZIP)» доступна сразу после анализа и не
требует выбирать методы. Она экспортирует все созданные Rodroid файлы, полный
`analysis.json` и манифест SHA-256.

ZIP содержит изменённую `libil2cpp.so`, полный `analysis.json`, список изменений
`changes.json` с SHA-256, исходными байтами для отката и инструкцию.
При сборке APK приложение проверяет, что выбранная библиотека совпадает с
`lib/arm64-v8a/libil2cpp.so` внутри исходного APK, заменяет её, удаляет старую
подпись, выравнивает нативные библиотеки и подписывает результат тестовым ключом.
Это постоянные изменения возвращаемых значений в копии библиотеки. Метод
возвращает константу вместо исполнения своего тела, включая побочные действия.
Проверка поведения в игре обязательна; автоматический анализ её не заменяет.

## Поддержка и границы

- Полный дамп выполняет Rodroid Il2CppDumper 0.7.0, закреплённый на commit
  `8bfb90229539833999e725c5cf6402a435b47f15`. В APK включены ARM64 и x86_64 сборки.
- Последующий анализ использует `script.json` и `dump.cs`, а не прежний сокращённый
  Python-парсер. Только положительные RVA из `script.json` считаются подтверждёнными.
- Кандидаты: не обобщённые, не абстрактные методы без аргументов с именем
  get_…/Get…/Is…/Has…, возвращающие bool, целые 8–64 бит, float или double.
  Имя — фильтр кандидатов, не доказательство назначения метода.
- При неизвестном типе/адресе, общем адресе или нехватке места патч не создаётся.
  Размер места оценивается по следующему известному адресу; это не полный
  дизассемблер и не доказательство всех границ нативных функций.
- Сохраняется инструкция BTI в начале метода, если она присутствует.
- Обфусцированные/зашифрованные таблицы, старые версии metadata, ARM32 и APS2
  пока не поддерживаются. Приложение сообщает причину, не подставляет адреса.
- Проверка пары файлов структурная. Совпадение всех структур не доказывает,
  что два файла точно относятся к одной сборке: выбирайте их из одного APK.
- Поддержана пересборка обычного APK с ARM64 IL2CPP. APKS/XAPK и split-наборы пока
  нужно предварительно свести к одному APK; их автоматическая сборка ещё не включена.
- Итог подписывается встроенным тестовым ключом ModKit. Он не обновляет официально
  подписанное приложение поверх существующей установки. Для публикации нужен ключ
  правообладателя.
- Отчёт можно экспортировать отдельно, в том числе при нуле кандидатов.
- При уничтожении процесса системой операция не возобновляется автоматически;
  после запуска приложение сообщает о прерывании, выбранные копии сохраняются.

## Сборка исходников

JDK 17 (полный, с javac/jlink), Python 3.12, Gradle 8.9, Android SDK 34 и
Build Tools 34.0.0. Задайте ANDROID_HOME и выполните из этой папки:

```
gradle --no-daemon assembleDebug lintDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`. Rodroid пересобирается скриптом
`scripts/build_rodroid_android.sh` при наличии Rust и Android NDK 26.3.
CI: `.github/workflows/mobile.yml`. Это отдельное приложение `dev.modkit.mobile`;
оно устанавливается рядом с прежним демонстрационным лоадером. Debug-подпись
предназначена для тестирования. Собственный постоянный ключ нужен для стабильных
обновлений и выпуска. Прежний генератор и демонстрация остаются в исходниках.

Python встроен в APK с помощью [Chaquopy](https://chaquo.com/chaquopy/doc/current/android.html).
Новый разбор стандартных структур основан на описаниях формата в
[MetadataClass.cs](https://github.com/Perfare/Il2CppDumper/blob/master/Il2CppDumper/Il2Cpp/MetadataClass.cs) и
[Il2CppClass.cs](https://github.com/Perfare/Il2CppDumper/blob/master/Il2CppDumper/Il2Cpp/Il2CppClass.cs).
Реализация мобильного пути: `modkit/mobile/engine.py`; прежний синтетический
metadata-парсер в мобильном сценарии не используется.
